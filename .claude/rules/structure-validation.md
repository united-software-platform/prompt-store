## Назначение

Единый стандарт структуры репозитория. Исключает произвольное размещение файлов, обеспечивает предсказуемую навигацию и автоматическую загрузку промптов инструментами.

---

## 1. Общие ограничения

- Только файлы `.md` — никакого исходного кода, YAML (кроме `SKILL.yaml`) и бинарных файлов.
- Максимальная вложенность: 3 уровня (`тип/категория/имя/файл.md`).
- Имена директорий и файлов — только `kebab-case` в нижнем регистре.
- Исключения по именованию: `SKILL.md`, `AGENT.md`, `COMMAND.md`, `SKILL.yaml`, `README.md`, `CLAUDE.md`, `.gitkeep`.
- Пустая категория обязана содержать `.gitkeep`.

## 2. Rules (`rules/`)

### Допустимые категории

| Директория       | Содержимое                                    |
|------------------|----------------------------------------------|
| `php/`           | Стиль PHP-кода, PSR-стандарты                |
| `architecture/`  | Clean Architecture, CQRS, DDD, Hexagonal     |
| `frameworks/`    | Symfony, Laravel, другие фреймворки          |
| `database/`      | SQL-паттерны, схемы, индексы                 |
| `documentation/` | Стандарты документации, шаблоны              |
| `devops/`        | CI/CD, Docker, деплой                        |
| `qa/`            | Стандарты тестирования                       |

### Структура файла правила

```text
rules/<категория>/<имя-правила>.md
```

### Обязательные секции

```markdown
# Название правила

## Назначение
Краткое описание — зачем это правило и когда применять.

## Правила
...

## Примеры
...
```

### Чеклист

- [ ] Файл лежит в одной из допустимых категорий.
- [ ] Имя файла в `kebab-case`.
- [ ] Присутствуют секции: `# Заголовок`, `## Назначение`.
- [ ] Нет ссылок на конкретные проекты — правила универсальны.

## 3. Skills (`skills/`)

### Допустимые категории

| Директория      | Содержимое                                      |
|-----------------|------------------------------------------------|
| `analysis/`     | Бизнес-анализ, требования, RAG                 |
| `architecture/` | Ревью архитектуры, проектирование систем       |
| `database/`     | Схемы БД, миграции, SQL-оптимизация            |
| `development/`  | Генерация моделей, нормализация данных         |
| `data/`         | Excel, табличные данные, отчёты                |

### Структура директории навыка

```text
skills/<категория>/<имя-навыка>/
  SKILL.md          ← обязательно
  SKILL.yaml        ← опционально
  references/       ← опционально, вспомогательные файлы
    *.md
```

### Обязательный фронтматтер `SKILL.md`

```yaml
---
name: <kebab-case, совпадает с именем директории>
description: "<когда использовать — триггерные слова и сценарии>"
tools: <список через запятую>
model: <opus | sonnet | haiku>  # опционально
---
```

### Чеклист

- [ ] Директория навыка содержит `SKILL.md`.
- [ ] Фронтматтер содержит `name`, `description`, `tools`.
- [ ] `name` совпадает с именем директории навыка.
- [ ] `description` описывает триггерные сценарии (когда вызывать навык).
- [ ] Навык лежит в одной из допустимых категорий.
- [ ] Вспомогательные файлы только в `references/`, не в корне директории.

## 4. Commands (`commands/`)

### Допустимые категории

| Директория   | Содержимое                                      |
|--------------|-------------------------------------------------|
| `review/`    | Ревью кода, безопасности, архитектуры           |
| `generate/`  | Генерация кода, моделей, миграций, спецификаций |
| `analyze/`   | Анализ архитектуры, БД, зависимостей            |
| `git/`       | Changelog, release notes, работа с git          |
| `init/`      | Инициализация проектов и модулей                |

### Структура файла команды

```text
commands/<категория>/<имя-команды>.md
```

### Обязательные секции

```markdown
# /<имя-команды>

## Описание
Что делает команда.

## Использование
/<имя-команды> [аргументы]

## Шаги выполнения
1. ...
2. ...

## Результат
Что получает пользователь на выходе.
```

### Чеклист

- [ ] Файл лежит в одной из допустимых категорий.
- [ ] Имя файла соответствует имени команды в `kebab-case`.
- [ ] Присутствуют секции: заголовок с `/`, `## Описание`, `## Использование`.

## 5. Agents (`agents/`)

### Допустимые категории

| Директория    | Содержимое                                        |
|---------------|--------------------------------------------------|
| `backend/`    | Backend-агенты (Ruby, Python, Go и другие)       |
| `database/`   | DBA-агент, агент работы с данными                |
| `devops/`     | Инфраструктурный агент, CI/CD                    |
| `qa/`         | QA-инженер, генератор тестов                     |
| `management/` | Project-manager, scrum-master                    |
| `analysis/`   | Системный аналитик, solution-architect           |

### Структура директории агента

```text
agents/<категория>/<имя-агента>/
  AGENT.md          ← обязательно
  references/       ← опционально
```

### Обязательный фронтматтер `AGENT.md`

```yaml
---
name: <kebab-case>
description: "<роль и специализация агента>"
tools: <список через запятую>
model: <opus | sonnet | haiku>
---
```

### Обязательные секции `AGENT.md`

```markdown
# Название агента

## Роль
Кто этот агент и какова его специализация.

## Когда использовать
Триггерные сценарии.

## Протокол работы
Пошаговый алгоритм выполнения задачи.

## Ограничения
Что агент не делает.
```

### Чеклист

- [ ] Директория агента содержит `AGENT.md`.
- [ ] Фронтматтер содержит `name`, `description`, `tools`, `model`.
- [ ] `name` совпадает с именем директории агента.
- [ ] Присутствуют секции: `## Роль`, `## Когда использовать`, `## Протокол работы`.
- [ ] Агент лежит в одной из допустимых категорий.

## 6. Добавление нового элемента (чеклист)

### Новое правило

1. Определить подходящую категорию в `rules/`.
2. Создать `rules/<категория>/<kebab-case>.md`.
3. Добавить секции: заголовок, `## Назначение`, `## Правила`, `## Примеры`.
4. Проверить: нет привязки к конкретному проекту.

### Новый навык

1. Определить подходящую категорию в `skills/`.
2. Создать директорию `skills/<категория>/<kebab-case>/`.
3. Создать `SKILL.md` с фронтматтером (`name`, `description`, `tools`).
4. Убедиться, что `name` совпадает с именем директории.
5. Вспомогательные файлы разместить в `references/`.

### Новая команда

1. Определить категорию в `commands/`.
2. Создать `commands/<категория>/<kebab-case>.md`.
3. Добавить секции: заголовок с `/`, `## Описание`, `## Использование`, `## Шаги`.

### Новый агент

1. Определить категорию в `agents/`.
2. Создать директорию `agents/<категория>/<kebab-case>/`.
3. Создать `AGENT.md` с фронтматтером и обязательными секциями.

### Новая категория

Если ни одна из существующих категорий не подходит:

1. Обновить этот документ — добавить категорию в соответствующую таблицу.
2. Обновить `CLAUDE.md` — добавить категорию в таблицу структуры.
3. Создать директорию с `.gitkeep`.

## 7. Запрещено

- Исходный код, тесты, `vendor/`, `node_modules/`, бинарные файлы.
- Файлы не в формате `.md` (кроме `SKILL.yaml`, `.gitkeep`).
- Вложенность более 3 уровней.
- Категории, не перечисленные в этом документе, без обновления документации.
- Имена директорий и файлов не в `kebab-case`.
