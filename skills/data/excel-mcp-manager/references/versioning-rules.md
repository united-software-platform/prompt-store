# Excel MCP Manager — Правила версионирования

Детальные правила определения версии файла с примерами и граничными случаями.

---

## Формат имени файла

```
{name}-v{release}.{revision}.xlsx
```

- `name` — базовое имя без версии (может содержать дефисы и цифры, но не `-v`)
- `release` — мажорная версия, целое число, начиная с 1
- `revision` — минорная версия, целое число, начиная с 0

**Примеры корректных имён:**
- `report-v1.0.xlsx`
- `budget-2024-v3.7.xlsx`
- `hr-employees-v2.0.xlsx`

**Новый файл всегда начинается с `v1.0`.**

---

## Таблица: тип операции → версия

| Операция | Тип изменения | revision | release |
|---|---|---|---|
| Изменение значения ячейки | DATA | +1 | без изменений |
| Добавление строк в существующий лист | DATA | +1 | без изменений |
| Удаление строк из существующего листа | DATA | +1 | без изменений |
| Обновление формулы | FORMULA | +1 | без изменений |
| Добавление новой формулы | FORMULA | +1 | без изменений |
| Изменение форматирования ячеек | FORMAT | +1 | без изменений |
| Объединение/разъединение ячеек | FORMAT | +1 | без изменений |
| Добавление строк в существующую таблицу | DATA | +1 | без изменений |
| Создание нового листа | STRUCTURE | сброс в 0 | +1 |
| Удаление существующего листа | STRUCTURE | сброс в 0 | +1 |
| Переименование листа | STRUCTURE | сброс в 0 | +1 |
| Копирование листа | STRUCTURE | сброс в 0 | +1 |
| Создание новой таблицы | STRUCTURE | сброс в 0 | +1 |
| Создание сводной таблицы | STRUCTURE | сброс в 0 | +1 |
| Создание диаграммы | STRUCTURE | сброс в 0 | +1 |
| Одновременно: данные + структура | STRUCTURE | сброс в 0 | +1 |

## Примеры перехода версий

### Обычные случаи

```
report-v1.0.xlsx  →  обновлены данные   →  report-v1.1.xlsx
report-v1.1.xlsx  →  форматирование     →  report-v1.2.xlsx
report-v1.2.xlsx  →  добавлены строки   →  report-v1.3.xlsx
report-v1.3.xlsx  →  новый лист         →  report-v2.0.xlsx
report-v2.0.xlsx  →  обновлены данные   →  report-v2.1.xlsx
report-v2.1.xlsx  →  удалён лист        →  report-v3.0.xlsx
```

### Переход через .9

```
report-v1.9.xlsx  →  обновлены данные   →  report-v1.10.xlsx
report-v1.10.xlsx →  новый лист         →  report-v2.0.xlsx
```

Revision не ограничен числом 9 — это не семантическое версионирование. `v1.10` после `v1.9` — корректно.

## Граничные случаи

### Одновременные структурные и данные изменения

Если в рамках одной задачи требуется:
- добавить новый лист И обновить данные в существующем

Результат: **release++** (приоритет у структурного изменения).

```
Пример: добавить лист "Итоги" и обновить значения в листе "Данные"
budget-v1.5.xlsx → budget-v2.0.xlsx  (не v1.6)
```

### Переименование листа

Переименование — это **release++**, даже если данные не изменились.

```
hr-v1.3.xlsx (лист "Employees") → hr-v2.0.xlsx (лист "Сотрудники")
```

### Форматирование таблицы vs создание таблицы

- Изменить стиль существующей таблицы → **revision++** (FORMAT)
- Создать новую таблицу из данных → **release++** (STRUCTURE)

### Копирование листа внутри книги

Добавление копии листа — это **release++** (STRUCTURE), так как структура книги меняется.

### Вставка/удаление столбцов

Вставка или удаление **столбцов** в существующем листе — это **revision++** (DATA/STRUCTURE зависит от контекста).
Если добавляется новое смысловое поле (колонка с данными нового типа) — можно трактовать как STRUCTURE и применить release++.
При сомнении — уточнить у пользователя.

## Процедура создания новой версии через MCP

### Шаг 1: Разобрать текущее имя файла

Из имени `report-v1.3.xlsx` извлечь:
- `name = "report"`
- `release = 1`
- `revision = 3`

Из имени `budget-2024-v2.0.xlsx` извлечь:
- `name = "budget-2024"`
- `release = 2`
- `revision = 0`

**Правило:** искать последнее вхождение `-v{цифры}.{цифры}` перед `.xlsx`.

### Шаг 2: Вычислить новое имя

Для **revision++:**
```
new_revision = revision + 1
new_name = "{name}-v{release}.{new_revision}.xlsx"
```

Для **release++:**
```
new_release = release + 1
new_revision = 0
new_name = "{name}-v{new_release}.0.xlsx"
```

### Шаг 3: Создать новый файл через побайтовое копирование

```bash
cp "/path/to/{old_name}" "/path/to/{new_name}"
ln -sf "{new_name}" "/path/to/{base_name}-last.xlsx"
```

`{base_name}` — часть имени без версии (например, для `report-v1.3.xlsx` → `report-last.xlsx`).

Ссылка `{base_name}-last.xlsx` всегда указывает на самую актуальную версию файла.

`mcp__excel__create_workbook` для создания версии **не использовать** — не переносит стили и метаданные.

### Шаг 4: Выполнить целевые операции

Все изменения применяются только к новому файлу. Оригинал остаётся нетронутым.

### Шаг 5: Записать в Changelog

Добавить запись в лист "Changelog" нового файла.

## Определение директории для нового файла

Новый файл создавать в той же директории, что и оригинал.

```
Оригинал: /home/user/documents/reports/report-v1.3.xlsx
Новый:     /home/user/documents/reports/report-v1.4.xlsx
```

Путь к директории извлекать из пути к оригинальному файлу.
